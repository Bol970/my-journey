# «Мой дневник»: Android-приложение и локальная веб-версия

> Исходное описание пользователя, вставленное в начале сессии 2026-11-02 без изменений. Уточнённые требования и решения смотрите в `2026-11-02-my-journey-design.md`. Если документы расходятся, верен проектный документ.

## Что получится

Личный дневник по образцу Journey: без подписки на приложение, с работой без интернета и синхронизацией через ваш Google Drive.

На телефоне устанавливается APK. На компьютере дневник запускается в браузере через локальный запускатель. Телефон работает независимо от компьютера. Записи и вложения шифруются отдельным паролем дневника.

## Возможности первой версии

- **Записи:** несколько записей за день, изменение даты, автосохранение, редактирование и корзина.
- **Редактор:** заголовок, текст, жирный, курсив, списки и ссылки. Фото, изображения и видео размещаются отдельным блоком.
- **Вложения:** выбор файлов, съёмка через системную камеру Android, просмотр фотографий и воспроизведение поддерживаемых видео. Оригиналы сохраняются без принудительного сжатия.
- **Организация:** хронологическая лента, календарь, поиск по тексту, фильтры по тегам и настроению. Настроение выбирается вручную из пяти уровней.
- **Местоположение:** получение координат по нажатию и разрешению пользователя, редактируемая подпись места, открытие точки во внешней карте.
- **Погода:** температура и состояние погоды через [Open-Meteo](https://open-meteo.com/). Полученное значение сохраняется в записи; ошибки сети не мешают писать. Для записей задним числом погода вводится вручную или сохраняется из импорта.
- **Перенос:** импорт ZIP из Journey и собственный зашифрованный экспорт с восстановлением.

Интерфейс русский, со светлой и тёмной темами. Основной сценарий: открыть дневник, нажать «Новая запись» и сразу писать.

## Техническое устройство

**Общий код.** React, TypeScript и Vite; редактор Tiptap. Android-сборка через [Capacitor](https://capacitorjs.com/docs), нативные возможности и фоновая работа на Kotlin.

**Локальное хранение.** На Android используются SQLite и закрытая папка приложения, в браузере IndexedDB. Сначала данные надёжно сохраняются локально, затем синхронизируются. Добавленные вложения копируются в хранилище дневника и не зависят от последующего удаления исходника из галереи. Вложения с другого устройства скачиваются при открытии; доступность без интернета показывается отдельно.

**Модель данных.** Запись содержит постоянный идентификатор, дату с часовым поясом, документ редактора, теги, настроение, место, погоду и ссылки на вложения. Отдельные сущности отвечают за версии записей, вложения и очередь синхронизации. Форматы хранения и экспорта имеют номер версии.

**Google Drive.** Android и веб-клиент регистрируются в одном Google Cloud-проекте. Используется Drive REST API и доступ только к [собственной области данных приложения](https://developers.google.com/workspace/drive/api/guides/appdata). Вход на Android выполняется через системную авторизацию Google, в браузере через Google Identity Services.

**Синхронизация.** Передаются отдельные записи и вложения с идентификаторами версий. Повторные попытки не создают дубликатов. Одновременные изменения сохраняются как конфликтующие версии с выбором пользователем. Удаления также синхронизируются, чтобы старое устройство не восстанавливало удалённые записи.

**Шифрование.** AES-256-GCM; случайный ключ дневника защищается ключом, полученным из пароля через PBKDF2-HMAC-SHA-256. Формат одинаков для браузера и Android. Тексты, теги, координаты, превью и вложения сохраняются зашифрованными; расшифрованный поисковый индекс существует только во время разблокированной сессии. Большие файлы обрабатываются частями.

**Фон на Android.** Kotlin WorkManager отправляет уже зашифрованную очередь, сохраняет прогресс и возобновляет передачу после прерывания. Для вложений по умолчанию используется Wi-Fi, с переключателем мобильной сети. Ограничения Android могут задерживать фоновые задания; после принудительной остановки приложения потребуется его открыть.

**Компьютер.** Локальный сервер раздаёт только файлы приложения на постоянном адресе `http://localhost:4173`, без доступа из локальной сети. Браузер синхронизируется, пока дневник открыт; при истечении доступа Google предлагает переподключение.

## Порядок реализации и перенос

1. Подготовить проект и проверить сквозной сценарий: зашифрованная запись создаётся на Android, появляется в браузере и изменяется обратно. Отдельно проверить фоновую отправку.
2. Реализовать редактор, ленту, календарь, вложения, поиск, настроение, место и погоду.
3. Добавить импорт из [ZIP-экспорта Journey](https://support.journey.cloud/en/categories/import-export-publish/articles/export-journal-entries-to-zip-format). Сопоставление полей проверить на реальном архиве пользователя.
4. При импорте сохранять даты, тексты, доступные метаданные и оригинальные вложения. Показывать количество перенесённых записей, пропуски и неподдержанные элементы; повторный импорт не должен создавать копии.
5. Подготовить подписанный APK, локальный запускатель и инструкцию по установке, Google Drive, экспорту и восстановлению.

## Проверка и исходные условия

Проверить следующие сценарии:

- запись без сети, перезапуск приложения и последующая синхронизация;
- одновременное редактирование и удаление на двух устройствах;
- обрыв загрузки большого видео, перезагрузка телефона, недостаток места;
- отказ в геолокации, недоступность погоды, истечение доступа Google;
- неверный пароль, повреждённые данные и восстановление на чистом устройстве;
- соответствие количества записей и вложений архиву Journey.

По умолчанию целевая среда: Android 8+ с сервисами Google и актуальные Chrome/Firefox на вашем Linux-компьютере. Публикация в Google Play и размещение публичного сайта в первую версию не входят.

Для подключения облака понадобится однократная настройка Google Cloud-проекта, для проверки переноса нужен ZIP Journey. Пароль дневника необходим для восстановления зашифрованных данных. Бесплатный объём Google Drive ограничивает общий размер дневника.
